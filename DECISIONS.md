# DECISIONS.md — Architecture & Trade-Off Log

Every non-obvious choice, trade-off, and measured cost is logged here with its rationale and measurement.

| ID | Date | Decision | Measurement / Constraint That Forced It | Measured Cost / Consequence |
|---|---|---|---|---|
| D-001 | 2026-11-10 | Priority Stance: Correctness > Latency > Concurrency / Admission > Quota Longevity | Brief requirement: "Never sacrifice correctness for speed: a wrong or fabricated answer is the worst failure mode." Bill is $0 on free tier. | Lower throughput under load; requests rejected or degraded rather than guessing or fabricating citations. |
| D-002 | 2026-11-10 | Latency SLO Targets: TTFT $p_{50} \le 2500\text{ ms}$, total $p_{95} \le 12\text{ s}$ under steady load | Target bounds for interactive user experience on research literature questions. | Under burst/overload, system shifts focus to admission control and queue bounding rather than chasing $p_{95}$. |
| D-003 | 2026-11-10 | Timing Model: TTFT includes queue wait + S1 Triage + S2 Retrieval + first-clause verification (`s5_first_flush`) | Zero hallucinated citations contract. User sees nothing until first clause is verified against retrieved chunks. | Added pre-flush verification latency overhead (typically 150–400 ms) before first visible token is emitted. |
| D-004 | 2026-11-10 | User Patience Budget: `PATIENCE_MS = 15000` (15s) | Human user abandon behavior: users give up after 15s in queue without response. | Requests waiting in queue > 15s are timed out with honest give-up notification; quota is not wasted on abandoned calls. |
| D-005 | 2026-11-10 | Timeout Ladder: Connect 5s, TTFT 12s, Inter-token gap 10s, Total 45s | Observed network and model inference delay bounds on free-tier infrastructure. | Fast termination of hung connections without holding resources indefinitely. |
| D-006 | 2026-11-10 | Retry Policy: Exponential backoff with jitter on 429/5xx, capped at 2 retries, circuit breaker cooldown on consecutive 429s | Provider burst rate limiting. Retrying blindly into a rate limit causes load amplification and worsens recovery. | Unretried non-429 4xx and content refusals fail fast; quota preserved. |
| D-007 | 2026-11-10 | Quota-Aware Steady Rate: Set `steady` scenario to 3 req/min (75% sustainable TPM ceiling) | Full answer costs ~2.5–3.5K tokens on 70B; Groq free 70B TPM is ~12K TPM and 100K TPD. 30 req/min would hit 429 in 15s and exhaust daily budget in 3 minutes. | Real-api steady run fires 15 requests over 300s safely within TPM limits; stress rates executed against calibrated stand-in. |
| D-008 | 2026-11-10 | Model Tier Migration: Swapped deprecated Llama models for `qwen/qwen3.8-27b` (S1 Triage & fallback) and `openai/gpt-oss-120b` (S4 Draft) | User directive / Provider model availability: Llama models discontinued on target deployment. | Configured per-model limits, pricing benchmarks, and stand-in latency/token characteristics for Qwen 27B and GPT-OSS 120B. |
| D-009 | 2026-11-10 | Stand-in Dynamic Synthesis & 50% Quota Simulation: Replaced canned mock strings with dynamic context-derived sentence synthesis and halved stand-in daily limits (50K TPD on 120B, 250K TPD on 27B) | User directive: Eliminate static/canned mock data in stand-in and simulate half-day quota to test degradation transition under load. | Stand-in generates realistic text synthesized from retrieved paper passages while reaching the 90% degradation ladder and 100% budget limit at half standard quota. |
| D-010 | 2026-11-13 | Recalibrated all limits from real Groq measurement: RPM=30 (429 body), TPM=8,000 (header), RPD=1,000 (header); TPD deliberately NOT probed (measuring it consumes the whole daily token budget) | Real 429 captured on burst probe #22 (27B) / #18 (120B); recovery ~2s; TTFT median 93 ms (27B) / 363 ms (120B) over streamed probes | Stand-in ttft_mu re-fit (ln 4.55 / 5.89); TPM assumptions corrected (6K/12K → 8K/8K); steady run paced at 3 RPM to fit the real budget |
| D-011 | 2026-11-13 | Budget ledger adopts limits observed in provider headers (x-ratelimit-limit-*) instead of trusting compiled assumptions | Brief: limits "can change without notice"; stand-in half-quota (RPD 500) was invisible to a client assuming 1,000 | Admission ladder keys off the most recently observed limit; assumed values used only before first response |
| D-012 | 2026-11-13 | Provider 429s that exhaust retries are classified `rate_limited` with an honest refusal, and the S5 draft loop never retries into a 429 | Overload run mislabeled 50/70 failures as `error`; retrying into quota exhaustion amplifies load without recovery (114 wasted retries observed) | Burst collapse is visible in Table 2b (80% rate-limited) instead of hiding inside `error` |
| D-013 | 2026-11-13 | Separate score-gate thresholds: BM25 gate 6.0 (unchanged), rerank gate 0.0 | Setting C refused 10/16 answerable questions because cross-encoder logits (−4.6..6.6 measured) sat below the BM25-scale gate | C's refusal rate fixed; its measured quality (56.2%) is now an honest retrieval finding, not a gate artifact |
| D-014 | 2026-11-13 | Chosen retrieval setting: B (150-token pieces, 12 fetched) normally, A-degraded (2 pieces) when the limit is close; C rejected | Measured: A/B/A-degraded all 62.5% correct; C 56.2% correct with TTFT p95 31.5 s (reranker on CPU); tokens 3,145 / 2,841 / 1,384 / 1,869 | Halves tokens per answer with no measured quality loss on this rubric; flagged assumption: a stronger reasoning draft model may need more passages |
| D-015 | 2026-11-13 | Evaluation sweep paces draft-model calls at 20 s (≈3 calls/min ≈ 8K TPM budget) and runs under scenario `eval`, excluded from Table 2 | First sweep lost 50% of rows to TPM 429s; availability failures were polluting quality percentages | Table 2 (load) and Table 3 (quality) now measure different things cleanly |
| D-016 | 2026-11-13 | **Performance phase**: proactive send-lease on measured RPM/TPM windows (headroom 0.9, booked before send, reconciled to actual tokens on completion); lease-aware retrieval degradation (wait estimate > 10 s ⇒ drop to A-degraded); AIMD adaptive concurrency (add-increase, multiplicative-decrease on 429s/slow TTFT, 1..8); queue-bound + patience re-checked while waiting; single-flight + 60 s cache for identical questions; shared pooled HTTP client; strict citation verification (exact tag membership — fixes a bypass where any section of a retrieved paper passed); S2 reranker moved off the event loop; triage JSON mode + graceful triage-quota degradation; per-source ledger files (real vs stand-in — a shared file let a stale per-minute header snapshot poison a whole day of stand-in runs) | Before/after measured on identical scenario definitions (results/archive/results_pre_optimization_baseline.csv vs results.csv): burst succeeded 20%→93.3%, overload 27.1%→88.6%, retries/req 1.73→0.10, rpm_halved succeeded 66.7%→93.3% with 14/15 auto-degraded instead of refused, tokens/answer −19…−54%, real steady TTFT p50 2006→1429 ms | Rate limits are now mostly avoided proactively (delayed, not refused); the residual tail is lease wait time under sustained overload, reported honestly as delay rather than hiding it in refusals |
